# 生产工程与多模态升级：实施记录

基线：2026-11-05，`f350587`，工作区干净。所有业务数据和容量场景均为模拟；以下目标不是既有成绩。本记录随实施更新，不以文档代替交付。

## 阶段及验收

1. **基线与模型协议（进行中）**：检查向量警告；通过显式协议配置接入 Responses，覆盖文本、工具往返、结构化输出、图片、流和失败路径；保持现有网关兼容。真实端点能力和模型质量须实测，不能按模型名推断。
2. **Case 与 Run**：演进现有工单，迁移旧记录；事务内校验 Case 版本和控制权，独立持久化业务动作幂等键，覆盖并发、接管、补材料、重新打开与旧草稿失效。Run 租约仍负责执行权。
3. **附件**：受授权的对象存储、校验、消息和 Case 引用、重试时重新授权；图片提取只产生候选事实，需数据库验证。
4. **政策和证据**：稠密、关键词和缓存共享政策版本与适用范围；扩展 SQL 结构化证据并同步生产者、消费者和契约；检测冲突和错误数字。
5. **身份和运行**：可信员工身份与权限，单公司共享业务只读范围；Compose、离机备份、恢复演练、同镜像发布及回滚。单主机不宣称高可用。
6. **自动验收**：冻结 200 个隔离场景、完整链路及独立权限/故障测试；报告覆盖率、拒答、成本、延迟、恢复和限制。Mock 不能证明真实模型质量。

## 编排决策

首版不引入 LangGraph。Case 是跨消息业务状态的权威来源，Run 存储负责单次执行的租约和检查点，工具调用记录负责执行过程；它们不可互相代替。等待材料时结束当前 Run，后续消息启动新 Run。现有模型调用尚未持久重放，须测量故障后的重复调用、恢复耗时和费用。

未来出现复杂审批或重新规划，或测量显示实质收益时，才局部试点图状态；保留队列、租约和 Case，明确 checkpoint 命名空间、并发写入、迁移、陈旧证据、重试预算和副作用幂等，并比较恢复、重复调用、p95 与维护成本。恢复中节点可能从头执行，框架不会自动保证外部副作用恰好一次。参考 [interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)、[persistence](https://docs.langchain.com/oss/python/langgraph/persistence)、[fault tolerance](https://docs.langchain.com/oss/python/langgraph/fault-tolerance)。

## 本次基线排查

本机离线客服题集使用 NumPy 2.2.6 / Apple Accelerate 时，矩阵乘法报告浮点警告；抽样输入与结果均有限，与独立逐行点积相差最多约 1.5e-8。该观察不能证明生产环境存在故障或完全确定底层原因。离线测试原先会吞掉流水线检索异常，因此需要显式断言。历史知识问答和 SQL 客服题集的模型、数据与限制仍以各自报告为准，不能当成当前 Sol 质量基线。

GPT-6.1 Sol 的工具调用使用 [Responses API](https://developers.openai.com/api/docs/models/gpt-6.1-sol)；[迁移说明](https://developers.openai.com/api/docs/guides/migrate-to-responses)要求转换函数输入输出、结构化输出和流事件。第三方兼容地址是否实现该协议尚未验证。
