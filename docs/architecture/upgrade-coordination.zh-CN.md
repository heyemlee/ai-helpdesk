## 协作约定

- 六个子对话使用同一项目，主对话按 1 → 2 → 3 → 4 → 5 → 6 顺序授予实施窗口。没有实施窗口的子对话只读检查并交回准备结果，不修改代码、切分支、安装依赖或操作运行服务。
- 一个时刻仅一个子对话修改业务代码。收到主对话的实施指令后，先重新检查 HEAD 和工作区，沿用前一阶段成果。主对话负责验收、反馈修复及继续派发；无需用户逐阶段批准。
- 子对话结束时返回：完成范围、提交、测试命令与计数、跳过或阻塞、下一阶段接口及限制。主对话读取完成结果收回，不要求子对话自行向其他聊天发消息。
- 所有提交使用英文 Conventional Commits，只提交本阶段文件。不覆盖他人改动，不执行全目录 add、reset、清理生产数据或未经请求的生产部署。不得把“实现代码”写成“已上线”。
- 根协调记录由主对话维护；子对话将实现和验收报告写入各自阶段文档。新接口务必贯通使用方，不交付无调用方的空壳作为阶段完成。

## 所有阶段共同要求

产品是单公司内部客服、销售和运营的订单与缺件/错货售后协作平台。保留 Python/FastAPI/Pydantic、PostgreSQL/pgvector、关键词检索、Redis Streams、独立 SQL Agent、A2A、React/TypeScript 和 Compose。模拟 ERP 数据不是实际经营数据；50 名员工、每周 3,000 次咨询是容量目标，不能当作真实采用。

生成、工具调用、图片理解使用 GPT-6.1 Sol API。Embedding 独立配置；不训练、不部署本地生成小模型，不引入必选 LangGraph。外部配置仅在本机安全读取、调用时使用，不输出密钥、不提交凭据、不要求用户把密钥粘贴进聊天。缺外部条件时仍完成不受影响的代码和自动验证，精确列明缺口。

后端测试遵循 test-backend 的隔离要求，实际入口使用受版本控制的 `.claude/skills/test-backend/scripts/run.sh` 与 `run-sql-agent.sh`；`.agents` 为已发现过期的本机副本，不作为门禁来源。存储、队列或事件改动跑 `--full` 的临时服务，不能接生产 PG 5433/Redis 6379。SQL Agent 测试同样隔离配置和数据；前端跑相关构建和自动流程。Mock 只能证明连线、故障和负载性质，不能报告成真实模型质量。测试跳过、限流、未执行不得记作通过。

## 六阶段交付范围

### 1. 模型协议和真实端点基线

审查 `c58c6dc` 的 Responses 适配，修复协议/状态/流/结构化输出/错误及工具往返缺口，保留既有保护、超时、限流和用量计量。同步 SQL Agent 独立传输层及连接设置；显式协议选择，不能按模型名推断第三方能力，不能静默回退后宣称通过。核对官方 Sol 文档。用现有凭据做有限真实能力探测（小输出、有限请求），记录地址类别而非密钥；没有凭据就明确标记未验证。为同模型、同配置、同数据的升级前后对比保留可复现基线。不修改运行中的生产配置。

### 2. 工单演进为跨消息 Case

复用工单入口和历史，不能造 Ticket/Case 两套竞争状态。Conversation 管沟通，Case 管同一业务问题，Run 管一次执行。一个会话可有多个 Case；FAQ 不强制创建。Case 保存订单/客户引用、问题类型、状态、负责人、附件引用、确认事实、待补字段、版本和消息/Run 关联。员工 actor 与业务客户引用分离。

状态 open/waiting_for_info/in_progress/resolved/cancelled，接管独立于生命周期，重开记录原因。材料变更递增版本；Run 绑定 expected_case_version；接管更新控制权版本。数据库条件更新或事务中拒绝旧结果，不以先读再判断代替并发保护。保留 Run 租约；等待材料释放 Worker，下一条输入启动新 Run。业务动作持久幂等，跨 Run 去重建单和通知。草稿绑定版本与证据，变更后失效；审批针对具体版本。明确 Case 引用优先，不能按订单号误合并多个售后；不确定的关联待确认。迁移须兼容旧记录与应用回滚，自动测试并发、接管、补料、重开和旧草稿。

### 3. 附件、图片核对与界面

打通 ChatRequest/前端上传、附件对象存储、消息持久化、Run 引用、Case 证据、重试和展示。数据库存归属/哈希/状态/提取结果，不存长期有效公开链接。每次读取执行后端授权；重试重新取访问权限。检查实际类型、体积、图片资源限制，图片文字不作为指令。对象存储支持离机配置和本地测试适配。优先订单截图、标签、配送/补件截图；订单号/型号/数量/状态/日期为候选事实，与 DB 核实，模糊/缺失/冲突产生待补字段。首版不自动判责赔偿。用浏览器自动流程和接口测试验收。

### 4. 政策适用与结构化证据

知识文档增加发布状态、版本、生效/失效、产品/区域/受众；先限制作用域再检索，稠密/关键词/缓存条件一致，支持显式 as-of。复用 SQL result_summary 的业务状态、风险、单位、来源和数据时点，结构化保存订单/字段/值/单位/时间/来源记录或查询 trace/证据 ID。关键金额/日期/型号/状态程序核对或直接渲染，草稿绑定引用。区分无记录、失败、冲突、截断和不可用。扩展 A2A 时同一提交同步生产者、消费者和 golden fixtures，服从契约 AGENTS。评测不能只检查正确数字出现而漏掉同回复错误数字。

### 5. 员工身份、部署准备、备份和恢复

可信员工登录，服务端验证 actor；员工/运营/管理员权限，模型/知识发布/数据源管理仅管理员。Case、附件、历史后端授权，浏览器不持下游管理 key。共享单公司业务只读范围；不声称完成行级隔离，不绕过已有 preflight 的 internal_single_tenant/impersonation 限制。

沿用 Compose，SQL Agent 单实例；离机附件/备份配置、PG/SQL 状态/必要配置自动备份、临时环境定时恢复验证、实际 RPO/RTO/规模报告。CI→镜像→临时环境→业务冒烟→同镜像发布→失败回滚；迁移需兼容应用回滚。单机不声称高可用，缺账号/域名/密钥可阻塞真正部署但不能阻塞本地准备和测试。保留和补充 Run/Case/模型/工具/旧结果拒绝/重复副作用指标，日志脱敏。生产部署技能仅按用户实际部署授权调用，不能因本任务自行操作生产。

### 6. 统一验收、质量/成本/性能/故障与发布门禁

冻结 200 场景：60 订单/生产/配送、50 政策、50 跨消息、40 图片。模拟 ERP/规则生成确定标准答案，按实体/模板/政策版本隔离开发与保留集，图片模板有变化。员工输入→Helpdesk→真实 SQL Agent/知识库（模拟业务数据）→最终草稿→Case 全链路，权限/幂等/故障另做确定性测试。程序校验事实、引用、状态、副作用；模型仅辅助表达评分，未覆盖不算通过。

候选发布固定配置三轮，日常相关子集并限制费用；缺凭据/限流/未跑完报告未完成，不偷换 Mock。浏览器自动流程；50 虚拟用户和周 3k 负载注明到达率/突发/并发/硬件及模型类型。目标事实正确率、跨消息成功率各 ≥95%，关键不变量全部通过；越权/重复动作/旧结果覆盖报告 0/N 而非绝对保证。图片按字段统计且模糊/冲突单列；知识、查库、图片 p50/p95 分开；两服务实际模型费用按咨询和成功任务统计；记录恢复/回滚时间和数据规模。Run 结束、业务解决和答对分别报告。所有报告记录提交、数据版本、模型/地址类别、配置、未完成和限制；历史 Luna 分数不能直接作为 Sol 的代码收益。
