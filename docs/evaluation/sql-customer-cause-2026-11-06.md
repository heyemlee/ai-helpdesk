## 修复内容与评分口径

原因尚不明确时，规划覆盖 Schema 中与该原因相关的生产、配送证据；一个来源的空备注不再成为省略另一来源的理由。用户明确只问某环节时仍只查该环节，普通整体状态查询仍保持一步。所有原因都缺失时保留未知，不由状态推断原因。

同一订单下多条问题的状态查询，需要能区分每条问题的类型或描述。首次重点回归暴露了只返回重复订单号和状态的遗漏；补充明细标识要求后，重新验证两道售后题，保留首次失败结果。

对“还要多久能到”，只有计划交付日期时返回计划日期，避免把过期计划与今天的差值当成真实等待时间；用户明确问日期差时仍计算，且明确参考日期。c03 与 c23 的标准答案没有改变。

c11 新增一条明确的等价参考：同一售后记录的问题描述与处理状态。原有问题类型与状态形式继续接受。逐行标识与状态必须成对一致，交换状态、遗漏问题、重复问题或只列状态均不能通过；新增离线用例覆盖这些反例。行列、风险、截断及矛盾检查保持原样，详见[判分修订 3](../../ai-sql-agent/benchmark/customer-rubric.md)。
